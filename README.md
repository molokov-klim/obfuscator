# obfuscator

Лексический обфускатор проекта для безопасной работы с LLM-агентом: по словарю замен строит копию проекта без реальных
имён, хостов и секретов, а изменения, сделанные агентом в копии, возвращает в оригинальный проект.

**Статус:** в разработке; работают `obfuscator obfuscate` и `obfuscator restore`, до выпуска 1.0.0 — проверки
производительности и на реальном проекте. Документы: [идея](spec/idea.md),
[требования](spec/requirements.md), [спецификация](spec/specification.md), [план](spec/plan.md).

## Установка

Нужны Python 3.12, [uv](https://docs.astral.sh/uv/) и git.

```bash
git clone <репозиторий> obfuscator && cd obfuscator
uv sync
uv run obfuscator --version
```

## Использование

### Словарь

TOML-файл с таблицей `[rules]`: ключ — оригинал, значение — алиас. Пример — `dictionary.example.toml`. Замена учитывает
регистр, поэтому каждое написание оригинала (`Pepelac`, `pepelac`, `PEPELAC`) — отдельное правило. Путь к словарю —
`--dict FILE` или переменная окружения `OBFUSCATOR_DICT`.

- Оригинал с точкой — в кавычках: `"db.host.internal" = "host-a7.example"`; без кавычек TOML читает ключ как
  вложенную таблицу (E01).
- Замена идёт и внутри слов: короткие или общеупотребительные оригиналы (`def`, `class`, `max`) испортят код копии
  (`default` → `<алиас>ault`). В словарь — только то, что действительно нужно скрыть; число замен по каждому правилу
  видно в отчёте.

### Обфускация

```bash
obfuscator obfuscate ~/Projects/demo --out ~/tmp/demo-x --dict ~/secrets/dictionary.toml
obfuscator obfuscate ~/Projects/demo/src ~/Projects/demo/README.md --out ~/tmp/demo-x   # несколько путей
```

- Под git в копию попадают только отслеживаемые файлы; без git — все файлы путей.
- `.obfignore` в проекте (синтаксис `.gitignore`, можно во вложенных каталогах) исключает файлы из копии.
- `.obfallow.toml` в корне перечисляет допустимые написания для проверки утечек:

  ```toml
  [[allow]]
  text = "max"              # точное написание
  files = ["src/**/*.py"]   # необязательно: только в этих файлах
  ```

- Рядом с копией появляется каталог состояния `<копия>.obfstate/` — он нужен для возврата, агенту его не давайте.
- Код выхода: 0 — успех (возможны предупреждения), 1 — отказ (ничего не создано), 2 — ошибка аргументов.
- `--verbose` — подробности по файлам.

### Возврат изменений агента

```bash
# способ A — сразу в рабочее дерево оригинала (только проект под git, без незакоммиченных изменений в путях входа)
obfuscator restore ~/tmp/demo-x --worktree --dict ~/secrets/dictionary.toml
git -C ~/Projects/demo diff        # посмотреть, затем закоммитить

# способ B — патч; оригинал не меняется
obfuscator restore ~/tmp/demo-x --patch ~/tmp/demo.patch
cd ~/Projects/demo && git apply ~/tmp/demo.patch
```

- Переносятся только изменения агента; строки, которых он не касался, остаются в оригинале байт в байт.
- Если оригинал в путях входа изменился после обфускации или прошлого возврата, возврат отказывается целиком (E22).
- Копия многоразовая: после возврата закоммитьте оригинал, и агент может продолжать в той же копии — следующий
  возврат перенесёт только новые изменения.
- Новые файлы агента, которые в оригинале игнорировались бы (`.gitignore`, `.obfignore`) или лежат вне путей входа,
  не переносятся и перечисляются в отчёте.
- Нужен тот же словарь, что при обфускации (иначе E21).

### Полный цикл

1. `obfuscator obfuscate <проект> --out <копия>` — копия без оригиналов.
2. Дайте агенту только каталог копии (не `<копия>.obfstate/` и не словарь).
3. `obfuscator restore <копия> --worktree` (или `--patch`), проверьте `git diff`, закоммитьте.
4. Повторяйте 2–3; чтобы начать заново — удалите копию и `<копия>.obfstate/` и обфусцируйте снова.

### Ошибки и предупреждения

При отказе (код выхода 1) ничего не создаётся и не меняется; каждая ошибка печатается строкой
`<код> <путь>[:<строка>] <сообщение>`; одинаковые находки (тот же код и написание) сворачиваются в одну строку
с числом и первыми местами — полный список даёт `--verbose`. Полная таблица — `spec/specification.md`, §7.

| Код | Что делать |
|-----|------------|
| E01–E06 | исправить словарь: формат, пустые или повторяющиеся алиасы, алиас внутри другого алиаса или содержит оригинал |
| E07 | проверить пути входа: существуют, все под одним git или все вне git |
| E08 | выбрать другой `--out`; для своей копии с изменениями агента — сначала `restore` |
| E09 | алиас уже есть в проекте — выбрать другой алиас |
| E10 | замена дала недопустимое для Windows имя файла — выбрать другой алиас |
| E11 | обратная замена неоднозначна на стыке алиаса и текста — выбрать другой алиас |
| E12 | в копии осталось написание оригинала: добавить его в словарь отдельным правилом или в `.obfallow.toml` |
| E13 | исправить `.obfallow.toml` или `.obfignore` |
| E20 | нет `<копия>.obfstate/` — копию нужно обфусцировать заново |
| E21 | для возврата нужен тот же словарь, что при обфускации |
| E22 | оригинал менялся после обфускации/возврата — закоммитить или вернуть свои правки, обфусцировать заново |
| E23 | закоммитить или убрать изменения в путях входа, либо использовать `--patch` |
| E24 | вход не под git — использовать `--patch` |
| E25 | новый файл агента совпадает с файлом оригинала — переименовать в копии или убрать файл в оригинале |
| E26 | установить git |
| E27 | выбрать другой файл патча вне копии и состояния |
| E28 | ошибка записи; изменения откатаны — устранить причину и повторить |

Предупреждения (W01–W14) не останавливают работу: оригинал в бинарном файле, пропущенная ссылка, правки агента с
оригиналом или алиасом в другом регистре, удаление, переименование, бинарные изменения — их стоит просмотреть.

## Проверки

```bash
uv run ruff check .          # линтер, docstring в стиле Google
uv run ruff format --check . # форматирование (исправить: uv run ruff format .)
uv run pyright               # типы, режим strict
uv run pytest                # тесты; производительность (SC-010): uv run pytest -m slow -s
```

Те же проверки запускает GitHub Actions на Linux и Windows при каждом push в `main`/`develop` и в pull request.

## Общие задачи разработки

Разработка идёт поставками: ассистент присылает архив `obfuscator-<версия>.zip` и одну команду, которая применяет
архив, ставит зависимости, запускает проверки, коммитит в `develop` и ставит тег `sdd/<версия>`.

### Первая поставка (в репозитории ещё нет скрипта синхронизации)

```bash
cd ~/Projects/obfuscator \
  && unzip -o -j ~/Загрузки/obfuscator-0.0.1.zip 'obfuscator-0.0.1/tools/sync_from_archive.sh' -d /tmp/obf-sync \
  && bash /tmp/obf-sync/sync_from_archive.sh ~/Загрузки/obfuscator-0.0.1.zip \
  && uv sync \
  && git add -A && git commit -m "0.0.1: <что сделано>" && git tag sdd/0.0.1
```

### Обычная поставка

```bash
cd ~/Projects/obfuscator \
  && tools/sync_from_archive.sh ~/Загрузки/obfuscator-<версия>.zip \
  && uv sync \
  && uv run ruff check . && uv run ruff format --check . && uv run pyright && uv run pytest \
  && git add -A && git commit -m "<версия>: <что сделано>" && git tag sdd/<версия>
```

Точная команда приходит с каждой поставкой. Вывод команды целиком отправляется ассистенту. Если упала проверка,
коммит не создаётся; рабочее дерево остаётся с файлами поставки — отправьте вывод ассистенту и верните дерево к
предыдущей поставке: `git reset --hard && git clean -fd` (игнорируемые файлы и файлы владельца не затрагиваются).

### Что делает скрипт синхронизации

`tools/sync_from_archive.sh`:

1. До любых изменений проверяет: рабочая копия чистая (неотслеживаемые файлы владельца из списка ниже допускаются); текущая ветка — из `.ai/delivery.env` архива; `HEAD` — это
   предыдущая поставка (тег `sdd/<base>`); файлы владельца игнорируются git.
2. Показывает, какие файлы будут удалены, изменены и добавлены, и спрашивает подтверждение (`y`).
3. Синхронизирует только файлы, отслеживаемые git. Не трогает никогда: `.git`, `.venv`, кэши, `uv.lock`, файлы
   владельца (`/.idea`, `/dictionary.toml`, `/runs`, `/logs`, `*.obfstate`) и любые файлы, игнорируемые git.

### Если скрипт остановился

| Сообщение | Что сделать |
|-----------|-------------|
| рабочая копия не чистая | `git status`; закоммитьте или уберите изменения (`git stash -u`), повторите команду |
| текущая ветка … а поставка для … | `git switch develop`, повторите команду |
| нет тега `sdd/<base>` | примените пропущенную поставку или сообщите ассистенту |
| HEAD не совпадает с поставкой | отправьте ассистенту вывод `git diff sdd/<base>..HEAD`: он перенесёт ваши изменения в следующий архив |
| файлы владельца не игнорируются git | добавьте путь в `.gitignore` или уберите из индекса: `git rm --cached <путь>` |
| отменено пользователем | ничего не изменено; команду можно повторить |

Любая остановка завершает скрипт с ненулевым кодом, поэтому коммит и тег не создаются.

### `uv.lock`

Создаётся и обновляется командой `uv sync` на машине владельца и коммитится вместе с поставкой. Скрипт синхронизации
его не трогает.

### После поставки

Отправка на GitHub и слияние в `main` — вручную:

```bash
git push origin develop --tags
```

Результат CI — во вкладке Actions репозитория; при падении отправьте ассистенту лог упавшего шага.
