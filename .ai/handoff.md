# Передача контекста

## Работа с владельцем

- Владелец: Molokov Klim. Язык общения, документов и `.ai/` — русский; идентификаторы, команды, пути, ID — без
  перевода.
- Процесс SDD по `.ai/kit/` (шаблоны) и первому сообщению сессии: документы → поставки «архив + одна команда».
- Стиль: суть сначала, без лести; вопросы в конце, самые важные первыми; ключевые решения — варианты с рекомендацией,
  решает владелец. Риск называется один раз; принятый риск записывается, а не оспаривается.
- Владелец предпочитает короткие ответы буквами вариантов («A», «B»); при двусмысленности — переспросить.

## Поставки

- Архив `obfuscator-<версия>.zip` с одним каталогом `obfuscator-<версия>/` — весь проект: код, тесты, `spec/`, `.ai/`.
- Команда — README → «Общие задачи разработки». Первая поставка берёт скрипт прямо из архива.
- `tools/sync_from_archive.sh`: проверки до изменений, подтверждение с `/dev/tty`, синхронизирует только файлы,
  отслеживаемые git; не трогает игнорируемые git, `/uv.lock`, кэши и файлы владельца. Списки исключений — в начале
  скрипта; при добавлении файла владельца обновлять `USER_EXCLUDES`, `USER_IGNORE_PROBES` и `.gitignore`.
- Версия — только в `pyproject.toml`; `.ai/delivery.env` совпадает с ней (скрипт сверяет). До выпуска
  `0.<этап>.<номер>`; тег `sdd/<версия>`.
- `uv.lock` порождается `uv sync` у владельца (в песочнице ассистента нет PyPI) — plan §9 п. 5.
- Проверки в песочнице: предустановленные `ruff`, `pyright`, `pytest`; `pathspec` есть только в системном Python 3.13;
  hypothesis нет. Непроверенное перечисляется в каждой поставке.

## Структура кода

Пакет `src/obfuscator/` (hatchling): `cli.py` — `main(argv) -> int`, коды выхода 0/1/2; `errors.py` — коды §7 и
`ObfuscatorError` (список находок); `models.py`; `dictionary.py`, `allow.py`, `state.py`; `narrow.py` — сужение
типов `tomllib`/`json` для pyright strict. Отказы собирают все находки сразу, а не первую.
Чистое ядро (без файлов и git): `trie.py` (регулярное выражение из префиксного дерева — обязательно для скорости),
`replacer.py` (один проход, самый длинный источник), `paths.py` (E10/W02),
`scanner.py` (перекрывающийся поиск без учёта регистра, E12/W10/W01/W11), `changes.py`, `merge.py` (построчное
восстановление: нетронутые строки — из оригинала).
Оболочка: `gitio.py` (порт `Git` + `SubprocessGit`), `ignore.py`, `inputs.py`, `fsio.py` (временные каталоги и
замена), `obfuscate.py` и `restore.py` (сценарии), `report.py`, `cli.py`. Интеграционные тесты — настоящий git во временных
каталогах, проекты строит `tests/factories.py`. Тесты: `tests/unit/`,
`tests/integration/`. Целевая структура — plan §2.1. Идентификаторы — английские, docstring и сообщения — русские
(Google style); в тестах docstring не требуются (plan §9 п. 7).

Проверка в песочнице ассистента (нет PyPI): `ruff check`, `ruff format --check`, `pyright` с временным
`pyrightconfig.json` (pythonPath — окружение предустановленного pytest, `extraPaths` — `src` и каталог с фиктивным
`obfuscator-<версия>.dist-info` для `importlib.metadata`), `pytest` с `PYTHONPATH=src:<этот каталог>:<каталог со ссылкой на pathspec из /usr/local/lib/python3.13/dist-packages>`;
для pyright тот же каталог pathspec — в `extraPaths`. hypothesis в песочнице нет: `tests/unit/test_properties.py` исключается из
pyright (`exclude` во временном конфиге) и pytest (`--ignore`), свойства проверяются отдельной случайной моделью.
