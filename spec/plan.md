Проект: `obfuscator` · Ревизия продукта: `rev1` · Владелец: Molokov Klim

## 1. Технологии

| Что | Выбор | Почему |
|-----|-------|--------|
| Язык | Python 3.12 | окружение владельца; `tomllib` в стандартной библиотеке |
| Окружение и зависимости | uv, `uv.lock` в репозитории | окружение владельца; воспроизводимая установка |
| Зависимость времени исполнения | `pathspec>=1.1` | семантика `.gitignore` для `.obfignore` и `files` в `.obfallow.toml` |
| Качество кода | ruff (lint + format, правила `D`, `convention = "google"`), pyright `strict` через `pyright[nodejs]` | окружение владельца; `[nodejs]` ставит Node вместе с пакетом, без скачивания при запуске |
| Тесты | pytest, hypothesis | юнит и интеграционные тесты; свойство обратимости на случайных данных |
| CI | GitHub Actions, матрица `ubuntu-latest` и `windows-latest` | SC-009, Q-6 |
| Внешние программы | git (на Windows — Git for Windows) | §4.2.2 спецификации |

**Факты этапа 0 (T-03) о песочнице ассистента:** доступа к PyPI нет (соединение с pypi.org отклоняется), поэтому
`uv sync`, `uv lock` и установка зависимостей проекта в песочнице невозможны. Есть предустановленные ruff 0.16.8,
pyright 1.1.414, pytest и Python 3.12/3.13; `pathspec` 1.1.1 — только в системном Python 3.13; hypothesis нет.
Следствия: архив проверяется предустановленными инструментами; тесты hypothesis, `pyright[nodejs]` и `uv.lock`
проверяются только у владельца и в CI — каждая поставка перечисляет это в «Не проверено»; `uv.lock` порождается
`uv sync` у владельца и исключён из синхронизации (§9 п. 5).

### 2.2. Модули и архитектура

- **Функциональное ядро, императивная оболочка.** `dictionary` (проверки), `replacer`, `paths`, `scanner`, `changes`,
  `merge` — чистые функции над строками, байтами и словарями: без файловой системы и git. Они покрываются юнит-тестами
  быстро и полностью. Оболочка — `inputs`, `gitio`, `fsio`, `state`, сценарии `obfuscate`/`restore`, `cli`.
- **Порт git.** `gitio` объявляет `Protocol` с методами из §4.2.2; сценарии получают его параметром. Интеграционные
  тесты используют настоящий git во временных репозиториях — подмена нужна только для редких ошибочных путей (E26).
- **Быстрый отказ.** Все проверки выполняются до первой записи; запись — в последнем шаге через `fsio` (временный
  каталог + переименование, откат из памяти).
- **Фикстуры строятся кодом** (`tests/factories.py`) в `tmp_path`, а не лежат файлами в репозитории: так байты с CRLF,
  BOM и не-UTF-8 не искажаются git-преобразованиями концов строк на Windows.

### 2.3. Поставки и версии

- Версия — только в `pyproject.toml`; до выпуска `0.<этап>.<номер поставки>`, выпуск — `1.0.0` с тегом `v1.0.0`.
- Каждая поставка — архив `obfuscator-<версия>.zip` и одна команда (README, «Общие задачи разработки»):

  ```bash
  tools/sync_from_archive.sh ~/Загрузки/obfuscator-<версия>.zip && uv sync \
    && uv run ruff check . && uv run ruff format --check . && uv run pyright && uv run pytest \
    && git add -A && git commit -m "<версия>: <что сделано>" && git tag sdd/<версия>
  ```

- До этапа 1 (нет кода) команда проверок сокращается до `uv sync`.
- `uv.lock` создаётся и обновляется `uv sync` у владельца, коммитится командой поставки; скрипт синхронизации его не
  трогает.
- Ветка разработки `develop`; push и слияние в `main` — владелец.

## 8. Риски

| Риск | Влияние | Что делаем |
|------|---------|------------|
| git ведёт себя не так, как записано в §4.2.2 (префиксы патча, `check-ignore` для несуществующего пути) | переделка возврата | T-01 до кода; T-40 повторяет проверки на Windows в CI |
| `pathspec` не даёт семантику вложенных `.gitignore` | ошибки исключений | T-02; при необходимости своя обвязка поверх `pathspec` |
| На Windows-раннере `core.autocrlf` меняет концы строк | ложные падения тестов байт в байт | фикстуры строятся кодом; во временных репозиториях `core.autocrlf=false` |
| `difflib.SequenceMatcher` медленный на очень больших файлах | долгий возврат | для сотен файлов несущественно; SC-010 меряет обфускацию, возврат меряем в T-60 и фиксируем |
| Регулярная альтернатива из сотен строк медленная (факт T-60: > 2 мин на 17 МБ и 500 правилах) | NFR-021 не выполняется | выражение из префиксного дерева, сканер через `lower()` (решение 9) |
| pyright требует Node | падение проверок без сети | `pyright[nodejs]`; T-03 |
| В песочнице ассистента нет PyPI | архив не проверяется полностью перед передачей | проверки предустановленными инструментами; непроверенное — в каждой поставке и в CI |
| Часть проверок невозможна в песочнице ассистента (Windows) | неполная проверка архива | в каждой поставке перечислено непроверенное; Windows — CI у владельца |

## 9. Решения

1. **Функциональное ядро без I/O.** Самые рискованные правила (замена, восстановление) тестируются быстро и полностью.
   Отклонено: классы-сервисы с файловой системой внутри — тесты медленнее и хрупче.
2. **Настоящий git в интеграционных тестах.** Поведение git — главный внешний риск; имитация его бы скрыла.
3. **Фикстуры кодом, не файлами.** Защита байтов от преобразований git на Windows.
4. **`pyright[nodejs]`.** Проверки работают без скачивания Node при запуске. Отклонено: basedpyright — владелец выбрал
   pyright.
5. **`uv.lock` порождается у владельца.** Ассистент не может выполнить `uv lock` без PyPI; файл коммитится командой
   поставки, скрипт синхронизации его не удаляет и не перезаписывает. Отклонено: присылать `uv.lock` в архиве —
   ассистент не может его построить.
6. **Сборка — hatchling, раскладка `src/`.** Распространённый бэкенд, `src/` исключает импорт пакета мимо установки.
7. **ruff: правила `E W F I N D UP B SIM PT RUF`; без `RUF001`–`RUF003`; `D` не требуется в `tests/`; `*.md` не
   проверяются.** Документация и сообщения — на русском, кириллица не опечатка; тесты именуются говорящими функциями
   без docstring; ruff ≥ 0.16 иначе форматирует блоки кода в `spec/*.md`.
8. **Долгие тесты помечаются `slow` и по умолчанию не запускаются** (`-m "not slow"`); запуск — `uv run pytest -m
   slow`.
9. **Префиксное дерево вместо простой альтернативы в регулярных выражениях; сканер без учёта регистра — через
   `lower()` и точный поиск.** Факт T-60 в песочнице: на 17 МБ и 500 непохожих правилах простая альтернатива не
   уложилась в 2 минуты, дерево — 2,0 с замена, 1,2 с сканер; полный тест SC-010 (1000 файлов, 20 МБ, 500 правил) —
