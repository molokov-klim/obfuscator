# Спецификация: obfuscator — лексический обфускатор проекта для работы с LLM-агентом

Проект: `obfuscator` · Ревизия продукта: `rev1` · Владелец: Molokov Klim
Документ: спецификация · Версия `1.1` · 2026-10-15 · Статус: утверждена
Цепочка: идея (`idea.md` 1.2) → требования (`requirements.md` 1.0) → **спецификация** → план (`plan.md` 1.3) → продукт и тесты

Спецификация фиксирует контракты: структуру проекта, конфигурацию, интерфейсы, форматы данных, правила обработки,
шаблоны вывода, коды ошибок. Отвечает на вопрос «какие обязательства», а не «в каком порядке» (это `plan.md`). Ссылки
FR-NNN, NFR-NNN, SC-NNN ведут в `requirements.md`.

Термины: **вход** — пути, переданные `obfuscate`; **корень** — общий корень входа (§5.2); **оригинал** — файлы входа в
исходном проекте; **копия** — каталог `--out`; **состояние** — каталог `<копия>.obfstate/`; **точка отсчёта** — снимок,
записанный в состоянии (§4.1.3).

---

## 1. Обзор

### 1.1. Компоненты

| Компонент | Кто исполняет | Что делает |
|-----------|---------------|------------|
| CLI | код | разбирает аргументы, вызывает сценарий, печатает отчёт, возвращает код выхода |
| Словарь | код | читает и проверяет словарь (§3.2, §5.1) |
| Заменитель | код | прямая и обратная замена за один проход (§5.3) |
| Вход | код | находит корень, набор файлов, применяет `.obfignore` (§5.2) |
| Пути | код | обфускация путей и проверка допустимости на Linux и Windows (§5.4) |
| Сканер утечек | код | поиск оригиналов без учёта регистра с учётом допустимых написаний (§5.5) |
| Обфускация | код | сценарий `obfuscate` (§5.6) |
| Состояние | код | чтение и атомарная запись `<копия>.obfstate/` (§4.1.3) |
| Возврат | код | сценарий `restore`: изменения агента, построчное восстановление, запись или патч (§5.7) |
| git | внешняя программа | только чтение репозитория и построение патча (§4.2) |
| Пользователь | человек | составляет словарь, `.obfignore`, `.obfallow.toml`; запускает команды; коммитит |

Модельной части в продукте нет: LLM-агент — внешний потребитель копии, инструмент с ним не взаимодействует.

### 1.2. Поток одного запуска

**Обфускация:** проверка словаря → разбор входа → набор файлов → проверка алиасов в проекте → прямая замена текста и
путей → проверка путей → проверка обратимости → сканирование утечек → запись копии и состояния во временные каталоги →
атомарное переименование → отчёт. Любой отказ до последнего шага не оставляет ничего на диске.

**Возврат:** чтение состояния → проверка словаря и его хэша → проверка оригинала → (для `--worktree`) проверка чистоты →
изменения агента относительно точки отсчёта → построчное восстановление → предупреждения → запись в оригинал или
патч → сдвиг точки отсчёта → отчёт.

### 1.3. Среда исполнения и безопасность

- Инструмент не обращается к сети (NFR-003).
- git вызывается как подпроцесс со списком аргументов, без оболочки; только команды из §4.2.
- Инструмент пишет только в: каталог копии, каталог состояния, файл патча, рабочее дерево оригинала (только `--worktree`,
  только в путях входа).
- В копию не попадают: `.git`, все `.obfignore`, все `.obfallow.toml`, файл словаря, каталог состояния (FR-012,
  FR-024, NFR-001).
- Отчёт печатается в консоль; в каталог копии ничего, кроме файлов копии, не пишется (NFR-002).

## 3. Конфигурация

### 3.1. Параметры запуска

Глобального конфиг-файла нет. Всё задаётся аргументами CLI (§4.2.1) и файлами проекта (§3.3, §3.4). Единственное
значение из окружения — `OBFUSCATOR_DICT`: путь к словарю, если `--dict` не передан. Если нет ни того, ни другого —
ошибка E01. Других значений по умолчанию нет.

### 3.2. Словарь (TOML)

```toml
# dictionary.example.toml
[rules]
"Pepelac" = "Zqv"
"pepelac" = "zqv"
"PepelacBig" = "Wmr"
"db.pepelac.internal" = "host-a7.example"
"Ivan Petrov" = "Person One"
```

- Единственная таблица верхнего уровня — `[rules]`; ключ — оригинал, значение — алиас, оба строки. Другие ключи — E01.
- Порядок правил не важен (§5.3). Повтор ключа запрещён форматом TOML — E01.
- Файл читается как UTF-8.

### 3.3. `.obfignore`

Файлы с семантикой `.gitignore` (шаблоны, `!`, `/` в начале и конце, `**`, комментарии `#`) в корне и в любых
подкаталогах корня. Шаблоны вложенного файла отсчитываются от его каталога, более глубокий файл переопределяет более
мелкий; файл в исключённом каталоге не читается и не может вернуть его содержимое — как в git (FR-019).

**Факты этапа 0 (T-02, `pathspec` 1.1.1):**

- `GitIgnoreSpec.check_file(path).include`: `True` — исключён, `False` — возвращён отрицанием `!`, `None` — ни один
  шаблон не подошёл.
- Шаблон каталога (`build/`) сопоставляется с путём каталога только с `/` на конце запроса (`"build/"`, не `"build"`);
  файлы внутри такого каталога сопоставляются и без этого.
- `pathspec` разрешает вернуть `!`-шаблоном файл из исключённого каталога (`build/` + `!build/keep.py` → файл не
  исключён), а git — нет. Поэтому реализация проверяет путь сверху вниз: сначала каждый каталог-предок (с `/` на конце),
  и если он исключён — файл исключён без дальнейших проверок; затем сам файл.
- Вложенность реализуется кодом: для пути берутся `.obfignore` всех каталогов-предков, путь передаётся относительно
  каталога каждого файла; решает самый глубокий файл с ответом не `None`.

### 3.4. `.obfallow.toml`

Читается только из корня (§5.2).

```toml
[[allow]]
text = "max"                   # точное написание (с учётом регистра), которое разрешено
files = ["src/**/*.py"]        # необязательно: шаблоны путей оригинала относительно корня; без поля — везде

[[allow]]
text = "PEPELAC_ENV"
```

- Каждая запись: `text` — непустая строка без переводов строк; `files` — необязательный непустой список шаблонов
  в синтаксисе `.gitignore`. Другие поля — E13.
- Разрешает находку сканера, если написание находки в точности равно `text` и путь файла попадает под `files` (или
  `files` нет). Для находок в путях копии используется путь самого файла.
- Используется и при обфускации (E12), и при возврате (W10).

## 4. Интерфейсы и данные

### 4.1. Форматы данных

#### 4.1.1. Модели кода

```python
@dataclass(frozen=True)
class Rule:
    original: str
    alias: str

@dataclass(frozen=True)
class FileEntry:
    original_path: str      # относительно корня, разделитель "/"
    copy_path: str          # относительно копии, разделитель "/"
    kind: Literal["text", "binary"]
    original_sha256: str
    copy_sha256: str

@dataclass(frozen=True)
class Finding:              # ошибка или предупреждение
    code: str               # "E12", "W10", …
    message: str
    path: str | None        # путь оригинала относительно корня
    line: int | None        # 1-based
    text: str | None        # найденное написание
```

#### 4.1.2. Отчёт в коде

```python
@dataclass
class Report:
    command: Literal["obfuscate", "restore"]
    ok: bool
    errors: list[Finding]
    warnings: list[Finding]
    counters: dict[str, int]                     # см. §6.1
    per_rule: dict[str, int]                     # оригинал -> число замен
    per_file: dict[str, int]                     # путь оригинала -> число замен
    files: dict[str, list[str]]                  # категория -> пути оригинала
```

#### 4.1.3. Каталог состояния `<копия>.obfstate/`

```
<копия>.obfstate/
  state.json          метаданные и точка отсчёта
  baseline/           снимок копии на точке отсчёта (обфусцированные файлы, те же относительные пути)
```

`state.json`:

```json
{
  "format": 1,
  "tool_version": "0.3.1",
  "created_at": "2026-10-15T19:30:00+03:00",
  "updated_at": "2026-10-15T20:10:00+03:00",
  "root": "/home/u/Projects/demo",
  "inputs": ["src", "README.md"],
  "git": true,
  "dictionary_sha256": "3b1f…",
  "files": [
    {"original_path": "src/app.py", "copy_path": "src/app.py", "kind": "text",
     "original_sha256": "…", "copy_sha256": "…"}
  ]
}
```

- Оригиналы в состоянии встречаются только в `root`, `inputs` и `original_path` (принятый риск, §9 п. 6). Содержимое
  оригинальных файлов не хранится: при возврате оригинал читается из рабочего дерева после проверки хэша.
- Запись атомарная: новая версия пишется рядом и заменяет старую переименованием.

### 4.2. Внешние интерфейсы

#### 4.2.1. CLI

```
obfuscator obfuscate PATH [PATH ...] --out DIR [--dict FILE] [--verbose]
obfuscator restore COPY_DIR (--worktree | --patch FILE) [--dict FILE] [--verbose]
obfuscator --version
python -m obfuscator …          то же самое
```

| Параметр | Смысл |
|----------|-------|
| `PATH` | файлы и каталоги входа (FR-060) |
| `--out DIR` | каталог копии; не существует, пуст или это собственная копия того же входа без невозвращённых изменений (FR-018) |
| `--dict FILE` | словарь; иначе `OBFUSCATOR_DICT` |
| `COPY_DIR` | каталог копии; состояние ищется в `COPY_DIR.obfstate/` |
| `--worktree` | способ A: запись в рабочее дерево оригинала (FR-034) |
| `--patch FILE` | способ B: файл патча; не должен существовать и не должен лежать внутри копии или состояния |
| `--verbose` | подробности по каждому файлу в отчёте |

Ровно один из `--worktree` и `--patch` обязателен (иначе код 2).

#### 4.2.2. git

| Назначение | Команда | Когда |
|------------|---------|-------|
| корень репозитория | `git -C <dir> rev-parse --show-toplevel` | разбор входа |
| отслеживаемые файлы | `git -C <root> --literal-pathspecs ls-files -z --cached -- <inputs>` | обфускация, проверка оригинала |
| чистота | `git -C <root> --literal-pathspecs status --porcelain=v1 -z --untracked-files=all -- <inputs>` | `restore --worktree` |
| игнор нового файла | `git -C <root> --literal-pathspecs check-ignore -q --no-index -- <path>` | возврат, FR-039 |
| патч | временный репозиторий, см. ниже | `restore --patch` |

**Построение патча.** Во временном каталоге (вне копии и состояния): `git init`; затронутые файлы оригинала в их
путях относительно корня; `git add -A`; `git commit`; затем новые версии файлов и удаления; `git add -A`;
`git diff --cached --binary --no-color --no-renames` → `FILE`. Все вызовы — с `-c core.autocrlf=false
-c core.quotePath=false -c commit.gpgsign=false -c user.name=obfuscator -c user.email=obfuscator@localhost`, чтобы
настройки пользователя не меняли байты и не требовали подписи. Временный каталог удаляется.

Отсутствие git, когда он нужен, — E26. Патч применяется пользователем из корня: `git apply <FILE>`.

**Факты этапа 0 (T-01, git 2.43, Linux):**

- `rev-parse --show-toplevel` вне репозитория — код 128; в подкаталоге репозитория — корень.
- `ls-files` для несуществующего пути — пустой вывод и код 0: существование путей входа проверяется до вызова (E07).
- Без `--literal-pathspecs` путь `x/a*b.txt` работает как шаблон и захватывает `x/aZb.txt`; с ним — только сам файл.
- `ls-files` выдаёт символические ссылки (режим 120000) и подмодули; они отсеиваются по типу файла в рабочем дереве
  (W03).
- `status --porcelain -- <пути>` показывает только изменения внутри путей, в том числе неотслеживаемые файлы.
- `check-ignore -q --no-index` работает для несуществующих путей (код 0 — игнорируется, 1 — нет); без `--no-index`
  отслеживаемый файл считается неигнорируемым.
- `git diff --no-index` для добавленных и удалённых файлов ставит в оба заголовка один каталог (`a/new/…`, `b/new/…`)
  и экранирует не-ASCII пути восьмеричными кодами, поэтому переписывание префиксов хрупко; вариант с временным
  репозиторием даёт чистые относительные пути.
- Патч из временного репозитория, применённый `git apply` в каталоге не под git, дал побайтно ожидаемое дерево для
  изменения с CRLF, добавления, удаления, бинарного файла и пути с пробелом и кириллицей.

## 5. Правила обработки

### 5.1. Проверки словаря (без проекта)

| # | Правило | Отказ |
|---|---------|-------|
| 1 | файл существует, это TOML со схемой §3.2 | E01 |
| 2 | правил не меньше одного | E02 |
| 3 | оригинал и алиас непустые, без `\n`, `\r`, `\0`; алиас без `/` и `\` | E03 |
| 4 | алиасы попарно различны (FR-005) | E04 |
| 5 | ни один алиас не входит в другой как подстрока (FR-007) | E05 |
| 6 | ни один алиас не содержит ни одного оригинала без учёта регистра (FR-008) | E06 |

Без учёта регистра везде в спецификации означает сравнение после `str.casefold()`.

### 5.2. Вход и набор файлов

1. Каждый `PATH` существует, иначе E07. Пути приводятся к абсолютным.
2. Для каждого пути (для файла — его каталога) определяется корень репозитория (§4.2.2). Все пути вне git — вход не под
   git; все в одном репозитории — вход под git; иначе E07 (FR-062).
3. **Корень:** под git — корень репозитория; не под git — общий предок путей, где для файла берётся его каталог, для
   каталога — он сам (FR-061). Разные диски Windows — E07.
4. **Кандидаты:** под git — вывод `ls-files` для путей входа, существующие в рабочем дереве обычные файлы (FR-010,
   FR-063); не под git — все обычные файлы внутри путей входа, без захода в каталоги `.git` (FR-011).
5. Пропускаются с предупреждением W03: символические ссылки, подмодули git.
6. Исключаются всегда: всё внутри `.git/`, файлы `.obfignore`, файлы `.obfallow.toml`, файл словаря, всё внутри каталога
   копии и каталога состояния (FR-012, FR-024).
7. Применяются `.obfignore` (§3.3).
8. Каталог копии не может быть внутри входа, а вход — внутри каталога копии: E08.
9. **Тип файла:** текстовый, если содержимое декодируется как UTF-8 строго; иначе бинарный (FR-015). BOM остаётся
   символом `U+FEFF`, переводы строк не преобразуются (FR-017).

### 5.3. Замена

- **Прямая:** одно регулярное выражение — альтернатива всех оригиналов (экранированных), отсортированных по убыванию
  длины, затем лексикографически; один проход слева направо; в каждой позиции берётся самый длинный подходящий
  оригинал (FR-003, FR-004, NFR-020). Регистр учитывается (FR-002).
- **Обратная:** то же для алиасов → оригиналов.
- Замена работает внутри слов: границы слов не учитываются.
- В бинарных файлах замена не выполняется (FR-016).

### 5.4. Пути

- Каждая часть пути (каталоги, имя файла с расширением) проходит прямую замену отдельно (FR-013).
- Часть пути копии недопустима (FR-014), если: содержит `< > : " | ? *` или символы с кодами 0–31; совпадает без учёта
  регистра с `CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9` (в том числе с любым расширением); оканчивается
  точкой или пробелом; длиннее 255 символов.
- Два пути копии, равные без учёта регистра, — конфликт (FR-014).
- Если недопустимость создана заменой — E10. Если такая же часть уже недопустима в пути оригинала — W02, копия
  создаётся (§9 п. 7).

### 5.5. Сканер утечек

- **Текст и пути копии:** альтернатива всех оригиналов без учёта регистра; находки с перекрытием (поиск в каждой
  позиции). Каждая находка, не разрешённая `.obfallow.toml`, — E12 с путём оригинала, номером строки и написанием
  (FR-020). Для путей номер строки не указывается.
- **Бинарные файлы:** поиск UTF-8 байтов каждого оригинала; без учёта регистра только для латинских букв ASCII,
  остальные символы — точно. Находка — W01 (FR-016). Сжатые форматы (zip, docx, png) поиском не покрываются —
  принятый риск (requirements, раздел 11).

### 5.6. Обфускация

1. Проверки словаря (§5.1).
2. Вход и набор файлов (§5.2); проверка `--out` (E08).
3. Ни один алиас не встречается (с учётом регистра) в тексте текстовых файлов и в путях набора — иначе E09 с путём и
   строкой (FR-006).
4. Прямая замена текстов (§5.3) и путей (§5.4).
5. Для каждого текстового файла обратная замена результата равна исходному тексту — иначе E11 (FR-022). То же для
   каждой части пути.
6. Сканер утечек (§5.5).
7. Запись копии во временный каталог рядом с `--out`, затем переименование в `--out`; так же для состояния. При ошибке
   временные каталоги удаляются (NFR-011).
8. Если `--out` — собственная копия того же входа: допускается, только если в ней нет изменений относительно точки
   отсчёта (иначе E08 с предложением выполнить `restore` или удалить копию); старые копия и состояние заменяются
   новыми.

### 5.7. Возврат

1. Чтение состояния (E20). Чтение словаря и проверки §5.1; хэш файла словаря равен `dictionary_sha256` — иначе E21.
2. `--worktree` при `git: false` — E24.
3. **Проверка оригинала (FR-036):** набор файлов, заново вычисленный по §5.2 для `root` и `inputs`, совпадает с
   `files[*].original_path`, и хэш каждого файла равен `original_sha256` — иначе E22 со списком расхождений.
4. **Чистота (FR-034):** для `--worktree` вывод `git status` по путям входа пуст — иначе E23.
5. **Изменения агента (FR-030):** обход копии (без каталогов `.git`) против `baseline/`:
   - одинаковый путь, разные байты — изменён;
   - только в `baseline/` — удалён (W12);
   - только в копии — добавлен;
   - пара «удалён + добавлен» с одинаковыми байтами — переименован (W13).
6. **Путь оригинала** для изменённого и удалённого — из `files`; для добавленного и переименованного — обратная замена
   каждой части пути копии (FR-031).
7. **Не переносятся (FR-039):** добавленные файлы, путь оригинала которых игнорируется `.gitignore` оригинала (под git,
   §4.2.2) или `.obfignore` (всегда). Они перечисляются в отчёте, предупреждения нет.
8. Добавленный файл, путь оригинала которого уже существует в оригинале, — E25.
9. **Построчное восстановление изменённого текстового файла (FR-032):** строки — части текста, разделённые по `\n`
   с сохранением разделителя. `B` — строки снимка, `C` — строки текущей копии, `O` — строки оригинала (число строк
   `O` и `B` совпадает по построению, §5.1 п. 3). Сравнение `B` → `C` (`difflib.SequenceMatcher`, `autojunk=False`):
   участок «равно» берётся из `O`; участки «замена» и «вставка» — строки `C` после обратной замены; «удаление» —
   строк нет.
10. Добавленный текстовый файл — обратная замена всего содержимого. Изменённый или добавленный бинарный файл, а также
    текстовый, ставший бинарным, — байты копии как есть (W14).
11. **Предупреждения по новым строкам `C` и путям добавленных файлов (FR-038):** оригинал без учёта регистра, не
    разрешённый `.obfallow.toml`, — W10; алиас без учёта регистра в месте, где нет точного совпадения, — W11, такое
    вхождение не восстанавливается.
12. **Запись:**
    - `--worktree`: новые версии всех файлов пишутся во временные файлы рядом с целевыми, затем по очереди заменяют
      целевые; удаления — последними; ставшие пустыми каталоги внутри путей входа удаляются. При ошибке уже заменённые
      файлы восстанавливаются из памяти — E28 (NFR-011).
    - `--patch`: патч строится во временном репозитории (§4.2.2) и пишется в `FILE`. В оригинал не пишется ничего
      (FR-035).
13. **Сдвиг точки отсчёта (FR-037):** `baseline/` := текущая копия (кроме непереносимых файлов п. 7); `files` и хэши
    оригинала — по новым версиям. Для `--patch` это ожидаемое состояние после `git apply`; если патч не применён,
    следующий возврат даёт E22.
14. Возврат без изменений — успех с нулевыми счётчиками; точка отсчёта не меняется.

## 6. Шаблоны вывода

### 6.1. Отчёт

Печатается в stdout; ошибки и предупреждения — также в stderr по одной строке `<код> <путь>[:<строка>] <сообщение>`.

```text
obfuscator obfuscate — OK
Вход: 2 пути, корень /home/u/Projects/demo (git)
Файлы: скопировано 120 (текстовых 115, бинарных 5); исключено 14 (.obfignore 10, служебные 4); пропущено 0
Замены: 342 в 57 файлах; путей изменено 6
  Pepelac → Zqv            120
  pepelac → zqv             98
  PepelacBig → Wmr          12
  …
Предупреждения: 1
  W01 assets/logo.png — оригинал в бинарном файле: «Pepelac»
Ошибки: 0
Копия: /home/u/tmp/demo-x
Состояние: /home/u/tmp/demo-x.obfstate
```

```text
obfuscator restore --worktree — OK
Изменения: изменено 3, добавлено 1, удалено 0, переименовано 0; не перенесено 2
Восстановлено замен: 27
Предупреждения: 0
Ошибки: 0
Следующий шаг: git -C /home/u/Projects/demo diff; затем закоммитьте изменения
```

- Пустой результат — тот же шаблон с нулями.
- Правила с нулём замен в сводке не выводятся.
- `--verbose` добавляет блоки «По файлам» (путь → число замен) и списки файлов по категориям.
- Для `--patch` последняя строка: `Патч: <FILE>; применить: cd <root> && git apply <FILE>`.
- При отказе первая строка `… — ОТКАЗ`, далее ошибки; копия, состояние, оригинал не изменены.

### 6.2. Прочие артефакты

- Копия — дерево файлов, ничего лишнего (NFR-001).
- Патч — формат `git diff --binary`; пустой патч не создаётся, вместо него отчёт «Изменения: 0».

### 6.3. Промпт модели

Нет.

## 9. Решения

1. **TOML для словаря и `.obfallow.toml`.** Стандартная библиотека (`tomllib`), все значения — строки без неявных
   преобразований типов.
2. **Одна команда с подкомандами `obfuscate` и `restore`.** Одна точка входа, общий разбор словаря.
3. **Нет глобального конфига.** Исключения — свойство проекта (`.obfignore`, `.obfallow.toml`), словарь — параметр
   запуска.
4. **Замена за один проход одним регулярным выражением.** Линейное время, не зависящее кратно от числа правил
   (NFR-020); C/Rust не нужны.
5. **Построчное восстановление.** Нетронутые строки берутся из оригинала, поэтому FR-032 выполняется по построению, а
   не проверкой; отсюда запрет переводов строк в словаре.
6. **Состояние рядом с копией (`<копия>.obfstate/`).** Выбор владельца. Риск: агент с доступом к родительскому каталогу
   прочтёт его. Мера: состояние не содержит содержимого оригинала — только обфусцированный снимок, хэши и пути
   оригинала; остаток (пути) принят.
7. **Уже недопустимый путь оригинала — предупреждение, а не отказ.** Отказ блокировал бы любой Linux-проект с `:` в
   имени файла, хотя инструмент эту проблему не создавал.
8. **Патч строится git во временном репозитории (`git diff --cached --binary`).** Только так `git apply` применяет и
   бинарные изменения; поэтому для `--patch` нужен git даже при входе не под git. Отклонено (T-01): `git diff
   --no-index` с переписыванием префиксов — хрупко для добавленных файлов и не-ASCII путей.
9. **Хэш словаря в состоянии.** Обратная замена корректна только тем же словарём; изменённый словарь — отказ E21.
10. **Файл словаря никогда не копируется.** Защита от случая, когда рабочий словарь лежит внутри входа не под git.
