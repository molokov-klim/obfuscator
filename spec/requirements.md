# Требования: obfuscator — лексический обфускатор проекта для работы с LLM-агентом

Проект: `obfuscator` · Ревизия продукта: `rev1` · Владелец: Molokov Klim
Документ: требования · Версия `0.1` · 2026-10-15 · Статус: черновик
Цепочка: идея (`idea.md` 1.1) → **требования** → спецификация (`specification.md` —) → план (`plan.md` —) → продукт и
тесты

Документ описывает, **что** должна делать система, без «как»: «как» — предмет спецификации и плана. Ключевые слова:
«обязательно», «рекомендуется», «можно». Номера сценариев, требований и критериев успеха стабильны: исключённые не
переиспользуются и остаются с пометкой « *Исключено в <версии>.*».

---

## 1. Цель

Дать пользователю возможность отдать проект LLM-агенту так, чтобы агент не увидел реальных имён, хостов и секретов, а
сделанные агентом изменения вернулись в оригинальный проект без ручного переноса и без порчи того, что агент не трогал.

## 2. Пользовательские сценарии

Приоритет: P1 — нужно в rev1, P2 — желательно, P3 — после.

### US-01. Обфускация проекта (P1)

Пользователь получает обфусцированную копию проекта, в которой нет ни одного оригинала из словаря, и видит, что и
сколько раз заменено.

- **Дано** проект и словарь без конфликтов, **когда** пользователь запускает обфускацию, **тогда** создаётся копия, в
  тексте и путях которой нет ни одного оригинала (в любом регистре), и выводится отчёт о заменах.

### US-02. Обнаружение утечки при обфускации (P1)

Пользователь узнаёт, что в проекте есть написание оригинала, не покрытое словарём, до того, как копию увидит агент.

- **Дано** проект, где встречается `pepelac`, и словарь только с правилом для `Pepelac`, **когда** пользователь
  запускает обфускацию, **тогда** копия не выдаётся, а ошибка называет файл, строку и найденное написание.
- **Дано** то же, но `pepelac` в этом файле внесено в исключения, **когда** запускается обфускация, **тогда** копия
  создаётся.

### US-03. Возврат изменений в рабочее дерево (P1)

Пользователь переносит изменения агента в оригинальный проект и смотрит их через `git diff`.

- **Дано** чистое рабочее дерево оригинала и копия с изменениями агента, **когда** пользователь запускает возврат
  способом A, **тогда** в рабочем дереве оригинала появляются изменения агента с восстановленными оригиналами, а файлы и
  части файлов, которых агент не касался, совпадают с прежними байт в байт.

### US-04. Возврат патчем (P1)

Пользователь получает изменения агента в виде патча и применяет его сам.

- **Дано** копия с изменениями агента, **когда** пользователь запускает возврат способом B, **тогда** создаётся файл
  патча, после применения которого `git apply` оригинал совпадает с результатом способа A на тех же данных.

### US-05. Повторный цикл (P1)

Агент продолжает работать в той же копии после возврата.

- **Дано** выполненный возврат, закоммиченный в оригинале, и новые изменения агента в копии, **когда** пользователь
  снова запускает возврат, **тогда** переносятся только изменения, сделанные после предыдущего возврата.

### US-06. Защита изменённого оригинала (P1)

- **Дано** оригинал, изменённый после обфускации или после последнего возврата, **когда** пользователь запускает
  возврат любым способом, **тогда** возврат отказывается целиком, перечисляет изменённые файлы, а оригинал остаётся
  нетронутым.

## 3. Границы

**Входит в rev1:**

- обфускация дерева файлов проекта в копию, включая пути (каталоги и имена файлов);
- проверка словаря на конфликты;
- проверка утечек в копии без учёта регистра со списком исключений;
- отчёты о заменах при обфускации и возврате;
- возврат изменений агента способом A (рабочее дерево) и способом B (патч);
- многоразовая копия: повторные возвраты из той же копии;
- предупреждения о подозрительных местах при возврате;
- Linux и Windows.

**Не входит в rev1:**

- режим поиска без учёта регистра (*исключён по итогам интервью*, см. Q-1);
- обработка бинарных файлов: копируются как есть;
- разбор синтаксиса языков;
- криптостойкость и стойкость к анализу;
- автоматический поиск секретов и генерация алиасов;
- интеграция с LLM; git-операции, меняющие репозиторий (коммиты, ветки);
- кодировки, кроме UTF-8;
- macOS.

## 4. Функциональные требования

### Словарь

- **FR-001.** Обязательно: словарь — файл пользователя с парами «оригинал → алиас»; путь к нему задаётся при запуске.
- **FR-002.** Обязательно: поиск оригиналов при замене учитывает регистр; другого режима нет.
- **FR-003.** Обязательно: оригинал заменяется везде, где встречается, в том числе внутри слова.
- **FR-004.** Обязательно: если в одном месте текста подходят несколько оригиналов, заменяется самый длинный.
- **FR-005.** Обязательно: инструмент отказывается работать, если два разных оригинала отображаются в один алиас.
- **FR-006.** Обязательно: инструмент отказывается работать, если алиас уже встречается в тексте или путях оригинального
  проекта.
- **FR-007.** Обязательно: инструмент отказывается работать, если один алиас входит в другой как подстрока.
- **FR-008.** Обязательно: инструмент отказывается работать, если алиас содержит оригинал (без учёта регистра).

### Состав копии

- **FR-010.** Обязательно: если проект под git, в копию попадают файлы, отслеживаемые git, за вычетом исключений из
  конфига.
- **FR-011.** Обязательно: если проект не под git, в копию попадают все файлы за вычетом исключений из конфига.
- **FR-012.** Обязательно: каталог `.git` не попадает в копию никогда.
- **FR-013.** Обязательно: оригиналы заменяются в каждой части пути — в именах каталогов и файлов, включая расширение.
- **FR-014.** Обязательно: инструмент отказывается создавать копию, если обфусцированный путь недопустим на Linux или
  Windows (запрещённые символы, зарезервированные имена) или два пути копии различаются только регистром.
- **FR-015.** Обязательно: текстовыми считаются файлы, которые декодируются как UTF-8; остальные — бинарными.
- **FR-016.** Обязательно: бинарные файлы копируются как есть; если в их байтах найден оригинал (без учёта регистра),
  выдаётся предупреждение с указанием файла.
- **FR-017.** Обязательно: концы строк (LF, CRLF) и BOM текстовых файлов сохраняются байт в байт.
- **FR-018.** Обязательно: каталог копии задаёт пользователь; инструмент не пишет в существующий непустой каталог, кроме
  копии, созданной им же для этого проекта.

### Проверка копии

- **FR-020.** Обязательно: после обфускации инструмент ищет все оригиналы в тексте и путях копии без учёта регистра;
  любая находка вне исключений — ошибка: копия не выдаётся, ошибка называет файл, строку и найденное написание.
- **FR-021.** Обязательно: исключения проверки задаются в конфиге: написание и, при необходимости, файл, где совпадение
  допустимо.
- **FR-022.** Обязательно: инструмент проверяет, что обратная замена копии даёт оригинал байт в байт; расхождение —
  ошибка, копия не выдаётся.
- **FR-023.** Обязательно: отчёт обфускации показывает число замен по каждому правилу и по каждому файлу, а также списки
  скопированных, исключённых и бинарных файлов.

### Возврат

- **FR-030.** Обязательно: инструмент определяет изменения агента в копии относительно точки отсчёта: изменённые,
  добавленные, удалённые и переименованные файлы.
- **FR-031.** Обязательно: в изменениях агента алиасы заменяются оригиналами, в том числе внутри слова и в путях.
- **FR-032.** Обязательно: файлы и части файлов, которых агент не касался, остаются в оригинале байт в байт.
- **FR-033.** Обязательно: способ возврата (A — рабочее дерево, B — патч) выбирает пользователь при запуске.
- **FR-034.** Обязательно: способ A записывает изменения в рабочее дерево оригинала и отказывается, если рабочее дерево
  не чистое.
- **FR-035.** Обязательно: способ B создаёт файл патча, который применяется к оригиналу командой `git apply`; в рабочее
  дерево оригинала способ B не пишет.
- **FR-036.** Обязательно: если оригинал изменился после обфускации или после последнего возврата, возврат любым
  способом
  отказывается целиком и перечисляет изменённые файлы.
- **FR-037.** Обязательно: после успешного возврата точка отсчёта сдвигается, и следующий возврат переносит только новые
  изменения агента.
- **FR-038.** Обязательно: при возврате выдаются предупреждения (перечень — раздел 7), возврат при этом продолжается.
- **FR-039.** Обязательно: новые файлы агента, которые в оригинале попали бы под `.gitignore`, не переносятся и
  перечисляются в отчёте без предупреждения.
- **FR-040.** Обязательно: отчёт возврата показывает изменённые, добавленные, удалённые и переименованные файлы, число
  восстановленных замен и все предупреждения.

### Состояние

- **FR-050.** Обязательно: всё, что нужно для возврата (точка отсчёта, ссылка на словарь), хранится вне копии.

## 5. Нефункциональные требования

### Безопасность

- **NFR-001.** Обязательно: в копии нет служебных файлов, содержащих оригиналы.
- **NFR-002.** Обязательно: отчёты и логи с оригиналами не пишутся в каталог копии.
- **NFR-003.** Обязательно: инструмент не обращается к сети.
- **NFR-004.** Обязательно: рабочий словарь пользователя не попадает в git; в репозиторий входит только пример словаря.

### Надёжность и воспроизводимость

- **NFR-010.** Обязательно: одинаковые проект, словарь и конфиг дают одинаковую копию.
- **NFR-011.** Обязательно: при ошибке не остаётся частично созданной копии, а при возврате способом A — частично
  изменённого оригинала.

### Производительность и стоимость

- **NFR-020.** Обязательно: время обфускации и возврата растёт линейно с объёмом текста и не растёт кратно числу правил.
- **NFR-021.** Обязательно: проект из 1000 текстовых файлов общим объёмом 20 МБ со словарём из 500 правил
  обфусцируется не дольше 10 секунд на обычном рабочем компьютере (*числа предложены ассистентом, см. Q-5*).

### Переносимость и сопровождение

- **NFR-030.** Обязательно: работает на Linux и Windows под Python 3.12.
- **NFR-031.** Обязательно: код проходит ruff, pyright (strict) и тесты pytest; docstring — Google style.
- **NFR-032.** Обязательно: словарь и настройки отделены от кода; README описывает установку, конфиг и полный цикл.

## 7. Перечни (начальные, уточняются в спецификации)

**Отказы (инструмент останавливается, ничего не создаёт и не меняет):**

1. два оригинала → один алиас (FR-005);
2. алиас встречается в оригинальном проекте (FR-006);
3. алиас входит в другой алиас (FR-007);
4. алиас содержит оригинал (FR-008);
5. недопустимый или конфликтующий по регистру путь копии (FR-014);
6. утечка оригинала в копию вне исключений (FR-020);
7. обратная замена копии не даёт оригинал (FR-022);
8. рабочее дерево оригинала не чистое при способе A (FR-034);
9. оригинал изменился после точки отсчёта (FR-036).

**Предупреждения при возврате (возврат продолжается):**

1. в изменениях агента найден оригинал (без учёта регистра);
2. в изменениях агента найден алиас в другом регистре — не восстанавливается;
3. агент удалил или переименовал файл;
4. агент изменил или добавил бинарный файл.

**Предупреждения при обфускации:**

1. оригинал найден в байтах бинарного файла (FR-016).

## 8. Критерии успеха

Все проверки — на синтетических фикстурах.

- **SC-001.** В копии синтетического проекта нет ни одного оригинала в тексте и путях без учёта регистра.
- **SC-002.** Обратная замена копии без изменений даёт исходное дерево байт в байт, включая CRLF, BOM и бинарные файлы.
- **SC-003.** Набор правок агента (изменение, добавление, удаление, переименование, новые пути с алиасами) после
  возврата способом A даёт ожидаемое дерево; файлы, которых правки не касались, совпадают байт в байт.
- **SC-004.** Патч способа B на тех же данных после `git apply` даёт то же дерево, что способ A.
- **SC-005.** Каждый отказ из раздела 7 воспроизводится на своей фикстуре с понятным сообщением; оригинал и каталог
  копии после отказа не изменены.
- **SC-006.** Написание оригинала в другом регистре даёт отказ с указанием файла и строки; после добавления в исключения
  обфускация проходит.
- **SC-007.** Второй возврат из той же копии переносит только изменения после первого.
- **SC-008.** Каждое предупреждение из раздела 7 воспроизводится на своей фикстуре.
- **SC-009.** Тесты проходят на Linux и Windows.
- **SC-010.** Выполняется NFR-021 на сгенерированном проекте указанного размера.
- **SC-011.** Полный цикл на реальном проекте владельца проходит без ручных правок и без утечек (проверяет владелец).

## 9. Класс риска

**R1.** Инструмент пишет в каталог копии и, при способе A, в рабочее дерево оригинала, которое обязано быть чистым под
git, — изменения откатываются средствами git. Внешних систем не меняет, в сеть не ходит.

Класс повышается, если способ A разрешить для проекта без git или для нечистого рабочего дерева: тогда изменения
оригинала не откатываются.

## 10. Допущения

- Пользователь сам составляет словарь и отвечает за полноту правил; проверка утечек находит только написания известных
  оригиналов.
- Агент работает только внутри копии.
- Для проектов под git на машине установлен git.
- Текстовые файлы проектов — в UTF-8.

## 11. Принятые решения и риски

| Решение                            | Риск                                                                         | Кто отвечает и мера                                                                                     |
|------------------------------------|------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------|
| Замена только с учётом регистра    | Пропущенное написание оригинала                                              | Инструмент: проверка утечек без учёта регистра — отказ (FR-020)                                         |
| Замена внутри слова                | Короткий оригинал заденет посторонние слова (`Max` в `Maximum`)              | Пользователь выбирает оригиналы; отчёт о заменах в каждом файле (FR-023); проверка обратимости (FR-022) |
| Бинарные файлы копируются как есть | Оригинал в сжатых бинарниках (zip, docx, png) не находится поиском по байтам | Пользователь: исключает такие файлы в конфиге; риск принят                                              |
| Возврат «всё или ничего»           | Любая правка оригинала после обфускации блокирует возврат                    | Пользователь: коммитит и обфусцирует заново                                                             |
| Многоразовая копия                 | Без коммита после возврата следующий возврат способом A отказывается         | Пользователь: коммитит после возврата; описано в README                                                 |
| Обфускация путей                   | Недопустимые на Windows имена после замены                                   | Инструмент: отказ (FR-014)                                                                              |
